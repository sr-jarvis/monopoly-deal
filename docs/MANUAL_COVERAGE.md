# Official manual coverage

## Authority and edition choice

- **E3113, PDF p.1**: Setup; On your turn; Playing cards; What if I owe another player money?; End of the game. Local extracted source: `E3113.txt` in task workspace. **E3113 p.2**: The cards; Wild Property Cards; House and Hotel Cards.
- **[B0965 official detailed cards, PDF p.1](https://instructions.hasbro.com/api/download/B0965_en-us_monopoly-deal-card-game.pdf)**: one physical PDF page, headed “The cards in more detail”; supplies explicit action targeting, counter-Just Say No, and valueless multicolor wild text. Download/extraction retained in task workspace as `B0965.pdf`/`B0965.txt`.
- **[Hasbro FAQ 953](https://hasbro-new.custhelp.com/app/answers/detail/a_id/953/~/monopoly-deal-%E2%80%93-does-a-just-say-no-card-count-towards-my-3-card-maximum-per)**: Just Say No does **not** count toward three plays, including on the actor's turn.
- E3113 is the default where editions differ: property cards **never** enter the bank, including ordinary property wilds. B0965's regular-wild banking sentence is deliberately not used. Multicolor wilds are always valueless and unpayable. Existing any-color Rent + Double The Rent behavior is retained; B0965 says “standard Rent” whereas the shipped deck's DTR card says “a rent card.”

## Integration and known limitations

1. **Transport integrated by Forge.** Public reaction projection, physical buildings, per-group completion, socket response handling, stable private seat recovery, bot acceptance-before-payment and human rematch are implemented and tested. The following describes the original worker handoff (now superseded): `app.js` must forward `ACCEPT_ACTION`, held JSN `cardId`, and optional `doubleRentCardIds`; resolve eligible bot responses before payment/turn driving, including out-of-turn bots. `room_registry.js` must project public `pendingActionResolution` (not internal `boardAfter`) and physical `buildings[color].houseCard/hotelCard`. Payment must not be offered before reactions resolve. Detailed handoff is `RULES_TRANSPORT_HANDOFF.md` in task workspace. Until integrated, raw-engine/SSR tests pass but end-to-end human reactions are not functional.
2. **Independent same-color sets are supported.** Legacy `Brown` is the primary identity; `Brown#2`, `Brown#3`, etc. identify additional independently arranged groups. Action `*PropertyColor` / `propertyColor` fields carry these group IDs; printed/native card color, rent matching, set size and building exclusions use the base color. Creation is implicit in property placement or a wildcard move to a new valid ID. Each group retains its own physical house/hotel. Deal Breaker transfers only the targeted set into an unused same-color ID on the receiver, never merges buildings. Compatibility for an old overfull pile takes the first printed set-size properties (plus its buildings), leaving surplus under the original key; it does not provide a subset picker for old piles. Wins deduplicate complete groups by base color. `same_color_sets.test.js` and the expanded rendered UI suite cover these contracts. Owner transport must preserve every dictionary key and publish `completedSetGroups` independently of distinct `completedSetColors`; see `SAME_COLOR_INTEGRATION.md` in the task workspace.
3. **Initial youngest-player selection is social.** No age collection exists; current seat order determines the first player. Participants can seat the youngest first.
4. **Browser interaction verified by Forge in a local deterministic two-client fixture.** Desktop 1440×1000 and phone 390×844: create/join/start, bank $5, place Brown property, target Debt Collector, held Just Say No cancellation and counter-pass, accept charge, select $3 bank asset for insolvent $5 demand, end turn, empty-hand draw-five and refresh preserving the exact seat. Preview Escape closes the dialog. Phone header overflow found and repaired. Screenshots and logs retained in private `.delivery/evidence`; these are automated interactions, not human testimony. The following describes worker-only evidence: Actual TSX render tests, lint and TypeScript/Vite build pass. No authorized isolated browser fixture was supplied to this worker; keyboard focus trap is implemented for the response dialog but not claimed as browser-tested. Broader legacy modal accessibility is not certified.
5. **Final owner checks supersede worker intermediate failures.** `npm test`: 667 passing plus 10 node:test assertions, exit 0, including two-socket deterministic complete match/win/rematch, held-card confidentiality, forged-identity rejection and reconnect. Client lint and type/Vite build pass. `npm audit --omit=dev` has zero vulnerabilities after scoped remediation (Zod 4.6.7 and qs 6.17.1). Development-only toolchain advisories remain documented in PRIVATE_V1.md. Independent immutable review and deployment are separately recorded in release evidence.
